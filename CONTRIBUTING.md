# Contributing

Thank you for helping improve Piano Fundamentals Trainer.

- Android tablet is the active product target. Keep changes within the documented scope unless a broader direction has been discussed first.
- Open an Issue before significant product behavior, contract, storage, MIDI, notation or security changes when practical.
- Preserve deterministic Sight Reading behavior and stable data/security boundaries. Do not casually alter existing contracts.
- Add or update focused deterministic tests for behavioral changes.
- Run `npm.cmd ci`, `npm.cmd run test:public`, a Debug APK build, Android shell checks and `git diff --check` before submitting a pull request.
- Never commit credentials, local signing files, APKs, private user data or machine configuration.
- Do not add copyrighted music, recordings, fonts or artwork without documented public redistribution permission and required attribution.
- Keep pull requests focused; avoid mixing architecture cleanup with a functional fix.
