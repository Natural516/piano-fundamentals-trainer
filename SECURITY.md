# Security policy

Please avoid publicly disclosing an exploitable vulnerability before maintainers have had a reasonable opportunity to review it.

Where GitHub private vulnerability reporting is available for this repository, use that private channel. If it is unavailable, contact the maintainers through their GitHub profiles without posting active secrets or exploit details in a public Issue. No response-time SLA is promised.

Never submit or attach:

- private signing keys or keystores;
- signing passwords;
- API keys, access tokens or credentials;
- production secrets or private user data.

If a credential was already exposed, revoke/rotate it through its provider before reporting the code defect. Ordinary bugs that do not contain sensitive security details may be filed as public Issues.

Official releases are distributed separately and signed by the maintainer-controlled Android release identity. A modified third-party build is not an official release.
