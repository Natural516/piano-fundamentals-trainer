## 最大的 10 个认知负担来源

1. **首页先让用户选模块，而不是告诉用户今天练什么。** 六张等权卡要求用户先做课程设计。
2. **训练计划同时承载五套工作。** 当前阶段、今日、每周、技术映射、六级验收并列，行动与管理混在一起。
3. **练习页同时是设置页、练习台、监控台和报告页。** 用户无法形成“开始后只练”的状态边界。
4. **实时统计过多。** 6–7 个累计指标与当前内容争夺注意，特别是节奏、音阶与协调练习。
5. **虚拟键盘在多个模块默认成为大块主视觉。** 它有教学价值，但不是每轮练习都必要。
6. **重复的设置输入。** 音阶速度预设 + BPM 滑杆、协调 BPM 数字 + 滑杆、题时预设 + 自定义同时出现。
7. **技术判定词直接暴露。** offset、sync warning、input window、Web MIDI API、noteOn/CC 迫使用户理解实现。
8. **曲谱练习把内容工具与架构工具并列。** Tier、MusicXML 校验、参考 MIDI、Teaching Playback、AI 和片段管理压过“练这一段谱”。
9. **结果页以 9–20 项指标网格开场。** 用户能看到分数，却不知道哪里最好、为何出错、下一轮怎么练。
10. **单次百分比冒充长期能力。** 正确率或掌握度百分比没有同时说明样本量、趋势、条件和原速证据。

## 推荐的新首页结构

从上到下固定为：

1. 今日问候 + 一行 MIDI 就绪状态。
2. **今日训练主卡**：3 项以内、总时长、顺序、唯一“开始今日训练”按钮。
3. **继续上次**：只保留一个可继续的练习上下文，不展示 3 条历史统计。
4. **近期状态**：一个谨慎的趋势结论；完整趋势进入“近期进步”。
5. **全部练习**：五大基本功 + 曲谱的紧凑次级入口，不再使用 6 张等权大卡。

## 推荐的新 Score Practice 结构

```text
练习前
  Level 1：曲名 + 大谱表 + 片段 + 手别/方式摘要 + 开始练习
  Level 2：练习方式、手别、BPM（仅需要时）、重复、预备拍
  Level 3：参考演奏、曲谱检查、练习建议、分段示范、片段管理、诊断

练习中
  乐谱 + 当前位置 + 简单进度 + 必要反馈 + 暂停 + 停止
```

“弹对后继续”不显示速度；“跟随速度/跟着示范弹”优先显示实际 BPM，原速百分比只作辅助。Tier 与内部时间/证据对象不进入用户界面。

## 推荐的练习结果页

首屏阅读顺序固定：

1. 做得最好：具体到小节/声部/拍点。
2. 最需要处理：只选一个最高价值问题。
3. 为什么：解释可观测证据与重要性，不解释算法。
4. 下一步：片段 + 手别 + 实际 BPM/练习方式 + 次数。
5. 主按钮：**按建议再练**。

“完成”是次按钮；正确率、错音、漏音、早晚、平均偏移等折叠到“查看详细数据”。证据不足时明确写“暂不判断趋势”。

## 尚未决定的问题

1. 当前工作树没有正式曲谱练习页面；需求中提到的 ScoreTime、Tier B、Reference MIDI 等应在哪个实际分支/版本继续做代码级盘点？
2. 今日训练的推荐顺序由现有固定计划、最近薄弱项还是用户手工顺序主导？F1 只定义呈现，不改 Planner。
3. 中途停止是否保存“未完成练习”，以及它是否参与趋势计算？原型推荐保存可解释的已完成部分。
4. “Wait”最终采用“弹对后继续”还是更短的“弹对继续”？建议真人可用性测试两版。
5. 基础练习的虚拟键盘默认是否应按用户水平记忆，而不是全局统一隐藏？
6. AI Coach 是结果页内的一条建议能力，还是仍需独立页面？若独立，必须限定在当前练习证据内。
7. 练习状态六档的最小样本量、时间窗口与“原速证据充足”阈值需要产品/教学共同定义。
8. MIDI 未连接时是否存在正式的键盘输入替代？当前原型只呈现检查连接，不新增替代功能。
9. 自由练习是否保留为正式产品能力；当前工作树只有占位页，F1 将它移出首页主视野。
10. 长期计划（阶段/每周/材料/验收）是一个页面的次级区，还是拆为独立“长期计划”空间？需要用真实内容量做下一轮验证。
