三、本阶段实际完成内容
==================================================

1. Android UI 接入真实共享识谱核心

已批准的 Android tablet UI 现在通过 A2.2 integration runtime 接入：

- src/sightReading/controller
- src/sightReading/midi
- src/sightReading/report
- src/sightReading/sightReadingSettings
- src/sightReading/musicKeySignatures
- src/sightReading/musicPitchSpelling
- src/sightReading/sightReadingNotes

没有创建第二套 Android-only 识谱引擎。

真实数据流为：

DevelopmentMidiAdapter
→ normalized SightReadingMidiEvent
→ SightReadingController.handleMidi()
→ 共享判题与计时状态机
→ Android UI snapshot

开发模拟按钮不会直接调用内部正确/错误处理函数。

2. Android V1 默认设置

实际默认值来自共享 ANDROID_SIGHT_READING_DEFAULTS：

- staffMode = grand
- keySignature = C
- notePoolMode = diatonic
- questionCount = 20
- answerTimeLimit = 5000 ms fixed
- noteNameVisible = false

没有错误继承 desktop 的 treble / noteNameVisible=true 默认值。

3. Settings 真实绑定

已批准的设置页现在可以修改下一轮内存会话：

- 谱表：高音谱表 / 低音谱表 / 大谱表
- 调性：现有全部 15 个大调
- 音符内容：调内音 / 含临时变音
- 题数：10 / 20 / 50 / 100
- 每题时限：固定 5 秒
- 显示音名：On / Off

设置使用注入式 InMemoryKeyValueAdapter。
页面 reload 后设置重置是本阶段允许行为。
没有使用 localStorage 作为 Android production persistence。

运行中的 session 会锁定设置，避免中途改变题袋与报告事实。

4. 真实题目与谱面

ACTIVE 谱面现在使用共享核心生成的真实 question 数据：

- 真实调号
- 真实音高拼写
- 高音谱表 / 低音谱表 / 大谱表 assignment
- accidentals
- ledger lines
- 正确 octave placement
- shuffled bag

继续复用现有 MusicStaffRenderer 与共享 notation/pitch primitives。
没有构造 Android 专用音乐理论实现。

接线保留了 A1/A2 Human-approved 的 ACTIVE 构图、staff 比例、clef 大小与 notehead 可读性。

5. Development-only 模拟 MIDI

新增 A2.2 · DEV 控制区，仅在 import.meta.env.DEV 下渲染。

支持：

- 答对
- 答错
- 指定 MIDI note number 并发送 NOTE_ON
- 重新开始开发会话
- 查看当前目标、phase、事件数与内存报告状态

事件约束：

- 单调递增 event ID
- timestamp 来自与 controller 相同的 injected clock domain
- NOTE_ON velocity > 0
- velocity=0 可经共享 normalization 变为 NOTE_OFF
- 不绕过 MIDI watermark
- 同 timestamp 仍可通过不同 ID 区分

没有增加 fake timeout 按钮。

6. 真实计时与反馈

以下行为全部由共享 SightReadingController 提供：

- question display 后 32 ms input lock
- 解锁后 5000 ms timeout
- first valid NOTE_ON 判定
- CORRECT
- WRONG
- TIMEOUT
- 约 350 ms feedback advance

UI 的倒计时条只读取 controller 的权威 remaining time，不自行制造判题事实。

7. 音名显示规则

显示音名 Off：

- ACTIVE 阶段不显示目标音名
- accessibility label 也不泄露答案音名

显示音名 On：

- ACTIVE 使用真实目标音名

判题后允许显示：

- 正确目标音名
- 错误时“目标 X · 弹成 Y”
- 超时时目标音名

8. 实时指标

ACTIVE 底部六项均绑定真实 controller facts：

- 完成
- 正确
- 错误
- 超时
- 当前连对
- 正确率

没有使用 Mock 计数。

9. Pause / Resume

暂停按钮已接入共享 controller。

共享契约继续负责：

- display 阶段 resume 后重新执行完整 32 ms lock
- answering 阶段冻结并恢复剩余 timeout
- feedback 阶段冻结并恢复剩余 feedback 时间

UI 增加清晰的 paused overlay，但没有重新设计练习表面。

10. Early End

“结束本轮”进入已批准的确认 UI。

继续练习：

- 调用真实 resume
- 回到当前真实 phase

结束并保存：

- 调用共享 controller.stop()
- 生成真实 stopped partial report
- completionState = stopped
- partialEvidence = true
- 保存到当前 runtime 的 in-memory report repository
- 返回 READY
- 不显示正常 completed RESULT

契约澄清：A2.2 不提供“继续上次练习”。

- confirmation dialog 中的“继续练习”只表示取消本次 stop，并恢复仍然存活的 session
- “结束并保存”会终止当前 session，保存 STOPPED partial facts，并返回 READY
- 已经 STOPPED 的 session 不可在 A2.2 中恢复

partial report 保留已完成的：

- completed
- correct
- wrong
- timeout
- accuracy
- reaction metrics（有证据时）
- best streak
- target-note error aggregates

11. 正常完成 RESULT

达到设置题数后，RESULT 使用真实 completed report：

- completed
- correct
- wrong
- timeout
- accuracy
- average reaction
- best streak
- 一个 primary most-error-prone target note

没有发明 top-N 算法。
没有错误音时显示中性“暂无”状态。
全部 timeout 导致 averageReactionMs=null 时显示“—”，不伪造 0 秒样本。

12. Mock 边界

以下页面仍保持允许的 Mock 范围：

- History：保留现有批准的 Mock 内容
- MIDI：明确标注 Mock，明确说明尚未接入蓝牙
- Update：明确标注不执行网络请求或 APK 更新

Home 可以显示当前真实识谱设置。
模拟 MIDI 不会被描述成真实 FP-30X Bluetooth 连接。
